# ADR 0001: ASCII Art Markdown File Constraints

These rules apply to every ASCII art markdown file in `ascii/` at the repository root.

## Status

Accepted on 2026-05-06. Authors: Tutorial Author.

## Context: Technical Requirements

We want agents to create ASCII art files for letter A-Z and numbers 1-100. We will
produce them in batches, refining our approach along the way. This file
includes technical requirements for the ASCII art we envision creating. 

This ADR pins down the **shape, size, and shell** of every ASCII art file so
that humans and agents both understand decisions we've made about constraints
and technical requirements. 

Aesthetic concerns (stroke style, case symmetry, visual balance) are not addressed
here. Visual design and content design standards are to be determined.

## Decision

Every ASCII art markdown file MUST satisfy the rules below. A rule's ID names its group and its number within that group, so `ART-2` is the second ASCII art constraint.

### Rules

**Location and naming**

- **LOC-1** MUST: Files live in `ascii/` at the repository root, with no subdirectories.
- **LOC-2** MUST: Each file is named `<character>.md`, where `<character>` is either a single lowercase letter `a`–`z` (`a.md`, `z.md`) or a 1-to-3-digit decimal number from `1` to `100` (`1.md`, `42.md`, `100.md`).
- **LOC-3** MUST: `ascii/` holds no files other than the ones LOC-2 names.

**File structure**

- **FILE-1** MUST: The file has exactly one H1 heading, whose text is the character itself, uppercased for letters and the bare digits for numbers: `# A`, `# Z`, `# 42`.
- **FILE-2** MUST: The file has exactly one fenced code block, with the language identifier `text`, holding the ASCII art.
- **FILE-3** MUST: The file has exactly one rhyme, a 2-line couplet of plain prose immediately below the code block, with no heading of its own.
- **FILE-4** MUST: The file holds those three elements in that order and nothing else: no additional sections, headings, blockquotes, lists, images, links, HTML, or trailing content.

**ASCII art constraints**

- **ART-1** MUST: The ASCII art inside the code block is at most 40 lines tall, not counting the fence lines.
- **ART-2** MUST: The ASCII art inside the code block is at most 40 columns wide, measured as the character count of its longest line.
- **ART-3** MUST: The ASCII art inside the code block uses printable ASCII characters only, code points `0x20`–`0x7E`, with no tabs, no non-ASCII, and no trailing whitespace on any line.

**Rhyme constraints**

- **RHYME-1** MUST: The rhyme is exactly 2 lines of text.
- **RHYME-2** MUST: Each rhyme line is a single sentence fragment or sentence, and the two lines rhyme.
- **RHYME-3** MUST: The rhyme is plain text, with no markdown formatting: no bold, italics, links, or inline code.

### Verify

Each command prints nothing when every file in `ascii/` conforms.

```bash
# LOC-1: nothing nested below ascii/
find ascii/ -mindepth 2
# LOC-2, LOC-3: filenames outside the allowed set
ls ascii/ | grep -Ev '^([a-z]|[1-9][0-9]?|100)\.md$'
# FILE-1: files without exactly one H1
grep -Hc '^# ' ascii/*.md | grep -v ':1$'
# FILE-2: files without exactly one text code block
grep -Hc '^```text$' ascii/*.md | grep -v ':1$'
# ART-1, ART-2: art taller than 40 lines or wider than 40 columns
awk 'FNR==1{n=0} /^```text$/{f=1;next} /^```$/{if(f&&n>40)print FILENAME": "n" lines";f=0;next} f{n++;if(length>40)print FILENAME":"FNR": "length" columns"}' ascii/*.md
# ART-3: tabs, trailing spaces or non-ASCII inside the art
LC_ALL=C awk '/^```text$/{f=1;next} /^```$/{f=0;next} f&&(/[^ -~]/||/ $/){print FILENAME":"FNR}' ascii/*.md
```

**Accept when:**

- Every command under Verify prints nothing.
- Each file the change adds or edits in `ascii/` follows every rule above.
