## Objective

By the end of this exercise you will have registered the `ascii-art` rig, dropped in the locked ADR and `ASCII.md` reference doc, pushed the rig to a fresh GitHub repo, and seeded 138 beads (12 epics + 126 child tasks) — so every later page in this tutorial has real work to dispatch.

## Prereqs

- [Page 00.1](./00.1-setup-foundation.md) complete: `factory1` city stood up with the setup pack imported.
- A **fresh, empty GitHub repository** for the `ascii-art` rig — your own org or a sandbox.

## Setup

### 1. Register the ascii-art rig

Register a rig as a **sibling** of the city (not a child of it). This is the project the factory will work on; we want the rig directory to live alongside `factory1/`, not inside it:

**Directory tree**

```text
software-factory-intensive/
  ├── factory1/      # the Gas City
  └── ascii-art/     # the rig
```

`gc` resolves the relative path to an absolute one internally and creates the directory if it doesn't already exist. The command also updates your `city.toml` (adds a `[[rigs]]` entry for `ascii-art`) and writes the absolute path to `.gc/site.toml`.

**Copy and paste**

```bash
cd $FACTORY_PATH

mkdir ../ascii-art
gc rig add ../ascii-art ascii-art
export ASCII_ART_PATH="$(cd ../ascii-art && pwd)"
echo "$ASCII_ART_PATH"
```

The `export` is important — every later step (and every later page) references `$ASCII_ART_PATH`. Without it, the variable lives only in your current shell's local scope and disappears the moment you spawn a subshell or open a new terminal.

**Outcome:** `../ascii-art/` exists as a sibling of `factory1/`, is registered with the city, `$ASCII_ART_PATH` holds the absolute path you'll need later.

See the new rig in the `city.toml` file.

**Copy and paste**

```bash
cat city.toml
```

**Expected output**

```text
[workspace]
provider = "claude"

[[rigs]]
name = "ascii-art"
```

The rig is also returned in the `gc rig list` command.

**Copy and paste**

```bash
gc rig list
```

**Expected output**

```text
Rigs in $FACTORY_PATH:

  factory1 (HQ):
    Prefix: fa
    Beads:  initialized

  ascii-art:
    Path:   $ASCII_ART_PATH
    Prefix: aa
    Beads:  initialized
```

### 2. Add starting docs

Start by exporting the tutorial and artifact paths.

**Copy and paste**

```bash
cd ../sf-tutorial
export TUTORIAL_PATH="$(pwd)"
export ARTIFACTS_PATH="$TUTORIAL_PATH/artifacts"
```

Then create the rig's `docs/` layout.

**Copy and paste**

```bash
mkdir -p "$ASCII_ART_PATH/docs/future" \
         "$ASCII_ART_PATH/docs/current" \
         "$ASCII_ART_PATH/docs/decision-records"
```

Finally, copy the ADRs in.

**Copy and paste**

```bash
cp "$ARTIFACTS_PATH/docs/decision-records/0001.ADR.ASCII.md" \
   "$ASCII_ART_PATH/docs/decision-records/"
cp "$ARTIFACTS_PATH/docs/future/0002.ADR.TESTING.md" \
   "$ASCII_ART_PATH/docs/future/"
```

**Outcome:** `$ASCII_ART_PATH/docs/decision-records/0001.ADR.ASCII.md` and `$ASCII_ART_PATH/docs/future/0002.ADR.TESTING.md` exist, and `$ASCII_ART_PATH/docs/current/` is empty.

### 3. Sanity-check the city

Run `gc doctor` against the city.

**Copy and paste**

```bash
cd $FACTORY_PATH
gc doctor
```

**Expected output**

```text
gc doctor
  ⚠ rig:ascii-art:git — not a git repository
```

You see one warning about the rig not being a git repository, so the next step is to initialize it.

### 4. Initialize git and push the rig

Branch protection (added later in [Progression page 03](./03-branch-protection.md)) needs an upstream `main` to attach to, so push the rig now. Replace `<your-github-handle>` below with the org or user that owns your fresh empty repo.

Create a new repository on GitHub by visiting [this URL](https://github.com/new?name=ascii-art&description=A%20reference%20project%20for%20a%20software%20factory%20to%20build.).

Now set up the local git repo:

**Copy and paste**

```bash
cd "$ASCII_ART_PATH"
git init -b main
git commit --allow-empty -m 'first commit'
git add docs/ .gitignore
git commit -m "Add docs describing initial vision for ASCII Art project"
```

Create a repo on GitHub named `ascii-art`, then add the remote and push:

**Copy and paste**

```bash
git remote add origin https://github.com/<your-github-handle>/ascii-art.git
git push -u origin main
```

**Outcome:** `git status` reports the working tree clean and the branch tracking `origin/main`.

### 5. Install the setup pack into factory1

Copy the pack into a `packs/` directory inside the city. `gc init` doesn't create that directory, so make it first:

**Copy and paste**

```bash
mkdir -p "$FACTORY_PATH/packs"

cp -r "$ARTIFACTS_PATH/packs/setup" \
      "$FACTORY_PATH/packs/setup"
```

Now register the new import at rig scope. Run from the city directory:

**Copy and paste**

```bash
cd "$FACTORY_PATH"

# Add the new pack at rig scope.
gc import add --rig ascii-art packs/setup
```

> **If you put the city itself under git,** commit `packs/` before you run `gc import add`. A path inside a git worktree is stored as a `file://` source pinned to the commit you have checked out, so an uncommitted pack has no HEAD to resolve and the command fails with `import version resolution failed: resolving HEAD ... empty response`. `gc init` doesn't create a git repo, so this only bites if you made one yourself. The same pinning means later edits to the pack need a fresh commit before the city picks them up.

Verify the rig now imports `setup`:

**Copy and paste**

```bash
gc import list --rig ascii-art
```

**Expected output**

```text
setup	packs/setup		(path)
```

Restart the city so the new patches and formulas take effect:

**Copy and paste**

```bash
gc restart
```

Confirm the new formula loaded and the refinery is pointed at it:

**Copy and paste**

```bash
gc formula list | grep -E "mol-refinery-patrol|mol-polecat-work"
```

**Expected output**

```text
mol-polecat-work
mol-refinery-patrol
```

### 6. Seed the beads queue

`gc rig add` should have run `bd init` for you. Confirm with `bd list` inside the rig.

**Copy and paste**

```bash
cd $ASCII_ART_PATH
bd status
```

**Expected output**

```text
📊 Issue Database Status

Summary:
  Total Issues:           0
  Open:                   0
  In Progress:            0
  Blocked:                0
  Closed:                 0
  Ready to Work:          0

For more details, use 'bd list' to see individual issues.
```

If you see this error: `Error: no beads database found`, run `bd init --prefix ascii-art` yourself.

Next, run the seed script to populate the beads database.

**Copy and paste**

```bash
cp "$ARTIFACTS_PATH/beads/seed-epics.sh" ./seed-epics.sh
chmod +x ./seed-epics.sh
./seed-epics.sh
```

**Expected output**

```text
Seed complete.
  epics opened: 12
  tasks opened: 126
  total beads:  138
```

## Try It

### 1. Sling a few beads

To manually start work, you *sling* a bead to an agent. You can sling directly via the CLI, or attach to your `mayor` agent's session and ask the mayor to do it. Try both variants below.

#### Variant A: Sling via the CLI

1. Find the epic for generating numbers 1–10. Use `bd list --type=epic`.
1. Find the tasks for generating numbers 1 and 2. Use `bd list --parent=<id>`.
1. From inside `factory1/`, sling a bead targeting the `ascii-art` rig. Two equivalent forms — try both:

**Copy and paste**

```bash
cd $FACTORY_PATH

# Specify the targeted rig and agent like this.
gc sling --rig ascii-art polecat <id-for-1>

# Or specify the targeted <rig>/<pack-providing-agent>.<agent> like this.
gc sling ascii-art/setup.polecat <id-for-2>
```

#### Variant B: Sling via the mayor in `tmux`

For a visual / conversational workflow, find beads via **beads-ui** in your browser, then attach to your `mayor` agent's session and ask it to assign the work.

First, find the bead for number 3 via beads-ui:

1. Install [beads-ui](https://github.com/mantoni/beads-ui).
1. In your terminal, run `cd "$ASCII_ART_PATH"`.
1. Start beads-ui with `bdui start --open`. Your browser should open to **http://127.0.0.1:3000** with an interface to browse your beads.

> **Note:** beads-ui supports multiple Beads projects but doesn't know where they live on your computer. Register additional projects by running `bdui start` in any project's root directory. Toggle between registered projects using the select list in the upper-left corner of the UI.
>
> **Tip 1:** Not sure if you're in a Beads project root? Run `ls -la`. If you see a `.beads` directory, you're in the right place.
>
> **Tip 2:** Run `bdui stop` when you're done — it avoids spurious error messages later. If you do hit them, ask Claude to troubleshoot.

Then ask the mayor to sling the bead for number 3.

When `factory1` is running, the `mayor` has a session running in the background continuously. You don't need to start a new Claude Code (or Codex, etc.) session — attach to the mayor's existing session via `tmux`:

**Copy and paste**

```bash
cd $FACTORY_PATH
gc session attach mayor

# WARNING: a `tmux` session will open which gives you direct access to the mayor's session. If you use `ctrl+c` it will interrupt its execution and you can ask it questions. However, be careful not to exit the agent with `ctrl+c` because that will kill the session within gas city. Instead, use `ctrl+b`, then `d` to safely detach from the session.
```

If that fails, or if you don't know the session alias to use, find it from inside `factory1/`:

**Copy and paste**

```bash
# list all named sessions and active ephemeral sessions
gc session list
gc session attach <alias-or-id>
```

Whenever you're unsure what's going on in your factory, attach to the mayor and ask. *What's the status of X? Why has Y finished? Are any agents working on Z?*

## Troubleshooting

- **`bd list` returns "No issues found" right after `seed-epics.sh`.** You almost certainly ran the script outside the rig directory, so the beads went into a different db (or no db at all). Run `pwd` — if you're not at `$ASCII_ART_PATH`, `cd` there and re-run the script.
- **`gh repo create` fails with auth or permission errors.** Run `gh auth status`. If unauthenticated, `gh auth login` and pick the org/user that owns your fresh empty repo. Confirm you have repo-create permission on that target.
- **`gc` can't find the rig.** The rig path binding lives in `.gc/site.toml` under a `[[rig]]` entry, written by `gc rig add` in step 1. If `gc rig list` doesn't show `ascii-art`, re-run `gc rig add ascii-art "$ASCII_ART_PATH"` from the city directory with the absolute path.
