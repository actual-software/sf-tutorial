## Objective

By the end of this hour `./preflight.sh` prints `PREFLIGHT: PASS` on your machine, which means every dependency the first session needs is installed at the version it was written against.

## Prereqs

- macOS or Linux, on amd64 or arm64.
- A GitHub account, and a repository you can push to for the rig.
- Roughly fifteen minutes, most of it waiting on downloads.

## Context

This block is staffed rather than taught. It runs over breakfast, it is opt-in, and its only purpose is that nobody discovers a broken toolchain at 10:15 while everyone else is registering a rig.

It is worth an hour of the schedule because of a failure that has already happened once. **Toolchain drift has broken a curriculum before.** An earlier version of this material was written against an older `gc`, and a newer one rejected `pack.toml` tables that used to be accepted, which broke the register chain partway through a session. Pinning is what stops that, and preflight is what proves the pins took.

The script reads the pinned versions out of [`deps.sh`](../bootstrap/deps.sh) rather than restating them, so there is one place to change a version and no way for the check to disagree with the installer.

One number is worth knowing before you install anything: `bd` and `dolt` land in `~/.local/bin`, and if that directory is not on your `PATH` then everything installs correctly and nothing works. Preflight checks for exactly that, because it is the single most common failure on a fresh machine.

## Setup

### 1. Clone the tutorial

**Copy and paste**

```bash
git clone https://github.com/actual-software/sf-tutorial.git
cd sf-tutorial/bootstrap
```

### 2. Install the pinned dependencies

`deps.sh` installs `bd` and `dolt` at the pinned versions into `~/.local/bin`, verifying each download's checksum first.

**Copy and paste**

```bash
chmod +x deps.sh preflight.sh
./deps.sh
```

**Expected output**

```text
two version lines, then: Installed to /Users/you/.local/bin. Ensure it's on your PATH:
```

Do what that last line says if you have not already:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Add it to `~/.zshrc` or `~/.bashrc` too, or you will re-learn this at 10:15.

### 3. Run preflight

**Copy and paste**

```bash
./preflight.sh
```

**Expected output**

```text
Platform
  [ ok ] os: darwin
  [ ok ] arch: arm64

Required tools
  [ ok ] git: /usr/bin/git
  ...
  [ ok ] gh auth: authenticated

Pinned dependencies
  [ ok ] PATH includes /Users/you/.local/bin
  [ ok ] bd: 1.0.3 (pinned)
  [ ok ] dolt: 2.0.1
  [ ok ] gc: /usr/local/bin/gc

Local path
  [ ok ] home directory is writable

PREFLIGHT: PASS
```

The last line is the only one that matters. `PASS` means you are ready. `FAIL` names the failing checks above it, and the checks are ordered so the first failure is usually the cause of the rest.

`./preflight.sh --install` runs `deps.sh` for you first, if you would rather do it in one command.

A `warn` line does not fail the run. It usually means a version drifted off the pin, which is worth mentioning to an instructor but is not a reason to stop.

## The cloud path

Skip this section if you are running the two days on your own machine. It is for participants working on a hosted box instead.

Getting onto the box is its own page. [`CLOUD_BOX_GUIDE.md`](../CLOUD_BOX_GUIDE.md) takes the four values your instructor sends you through to a running factory, and it is the one place those steps live. Work through it first, then come back here for the preflight run below.

### Run preflight against the box

**Copy and paste**

```bash
cd bootstrap
./preflight.sh --cloud
```

`--cloud` runs every local check first and then adds a "Cloud path" section.

**Expected output**

```text
Cloud path
  [ ok ] sfbox: /path/to/sf-tutorial/participant-box-cli/sfbox
  [ ok ] box credential: <boxId>
  [ ok ] box reachable: ssh, gc and the Gas City service all answered

PREFLIGHT: PASS
```

The reachability check delegates to `sfbox preflight`, which walks the three layers in order and stops at the first one that fails. That ordering is the useful part: it tells you whether the problem is SSH, a missing `gc`, or the Gas City service, so you know which of the three to fix instead of guessing.

If it fails, the failing layer is printed underneath the `[FAIL]` line. `sfbox preflight` on its own gives you the same detail while you work the problem.

One case sits between pass and fail: SSH and `gc` answer, but the Gas City service on the box is not running. That reads as a `[warn]` with `sfbox`'s own line printed underneath, because the box is yours to fix. If you have not done the first-run login yet, `sfbox` says so and names `sudo gas-city-login`; that is [step 5 of the box guide](../CLOUD_BOX_GUIDE.md#step-5-the-first-run-login). Otherwise `sfbox restart-factory` starts the service. Say so at breakfast rather than at 10:15 if it does not come back.

### If you are on a box, `~/.local/bin` still matters

The local checks above run against *your laptop*, and they stay meaningful on the cloud path because that is where you type commands. The box has its own toolchain, checked by the `gc installed` line inside `sfbox preflight`. Two machines, two toolchains, one preflight that covers both.

## Try It

Break it on purpose, once, so you recognise the failure when it happens for real:

**Copy and paste**

```bash
env PATH="/usr/bin:/bin" ./preflight.sh; echo "exit code: $?"
```

**Expected output**

```text
several [FAIL] lines, then:
PREFLIGHT: FAIL (n check(s) failed) — get paired before the first session
exit code: 1
```

That is what a missing `PATH` entry looks like. It is the same shape as "I installed everything and nothing works", which is the sentence this whole block exists to prevent.

## Verification

**Copy and paste**

```bash
./preflight.sh && echo "ready"
```

**Expected output**

```text
PREFLIGHT: PASS
ready
```

## Troubleshooting

- **`PATH is missing ~/.local/bin`.** Run `export PATH="$HOME/.local/bin:$PATH"`, then add the same line to your shell rc so a new terminal keeps it.
- **`gh auth: not authenticated`.** Run `gh auth login` and pick HTTPS. You need this before the rig gets pushed, which happens in the first hands-on block.
- **`bd: not found` right after `deps.sh` said it installed.** Almost always the `PATH` problem above. Confirm with `ls ~/.local/bin`.
- **A checksum mismatch during `deps.sh`.** A partial download. Re-run it; the script fetches to a temporary directory and cleans up after itself.
- **`gc: not found`.** Gas City installs separately from this tutorial's pinned dependencies: `brew install gascity` on macOS or Linux, or see [the Gas City README](https://github.com/gastownhall/gascity#installation) for a source build. Then re-run preflight.
- **`dolt` reports a different version than the pin.** That is a warning rather than a failure. It will probably work; mention it to an instructor so it can be ruled out if a later step misbehaves.
