## Objectives

By the end of this exercise you will have:
- A minimal Gas City "city" called `factory1`
- Gastown pack installed, making the `polecat` (worker) and `refinery` (reviewer) agents available to `factory1`

## Prereqs

- `gc` 1.1.0+ (run `gc version`)
- `bd` 1.0+ (run `bd --version`)
- `gh` 2.x authenticated to a GitHub account that can create repos (`gh auth status`)
- `git`
- macOS or Linux with `tmux` available
- You've read the [README](../README.md), so you know what you're building

**copy and paste**

```bash
gc version
bd --version
gh --version
git --version
gh auth status
```

Don't reinstall what you already have. Confirm versions, and if any are missing, follow the upstream install docs:

- `gc`: https://github.com/gastownhall/gascity (install instructions in the project README)
- `bd`: https://github.com/steveyegge/beads
- `gh`: https://cli.github.com/
- `git`: https://git-scm.com/downloads

## Context

We're starting with a simple 2-agent factory and workflow included with Gas City. The first agent will do work; the second will peer review its work and accept or reject. The next page ([00.2](./00.2-setup-foundation.md)) registers the `ascii-art` rig — the project we'll work on for our examples.

Run every step from a working directory you're happy to keep around — the city and (next page) the rig will live as sibling directories under it. Recommended:

**Directory tree**

```text
~Projects/
 └── software-factory-intensive/      # Create this. Rename it later if you want.
     ├── sf-tutorial/                 # Clone the tutorial repo here.
     ├── factory1/                    # Next Gas City will put this here via `gc init ...`
     ├── ascii-art/                   # Then Gas City will put this here with `gc rig add ...`
     └──── <your projects>            # You can add your projects here.
```

## Walkthrough

### 1. Create factory1

Create the `factory1/` directory with an auto-generated `city.toml` and `pack.toml`.

**copy and paste**

```bash
cd path/to/software-factory-intensive
gc init factory1
```

Follow the interactive prompt. Select:

- **gastown** config template (`2`)
- Claude Code (recommended) or whatever provider you are using

**copy and paste**

```bash
ls
ls factory1/
```

**Outcome:** `factory1/`, `factory1/city.toml`, and `factory1/pack.toml` exist.

### 2. Review the gastown pack installation

The `polecat` and `refinery` agent definitions ship in the gastown pack — which is **embedded inside the `gc` binary**, not fetched from a remote git repo. `gc init` (step 1) already dropped a copy at `.gc/system/packs/gastown/` inside your city. Confirm it's there:

**copy and paste**

```bash
# Run from the factory1/ city directory.
cd factory1
export FACTORY_PATH=$(pwd)
ls .gc/system/packs/gastown/agents
```

**Expected output**

```text
boot deacon mayor polecat refinery witness
```

The pack is on disk and your city's `pack.toml` imports it — that's what makes the agents "available" in factory1 and its rigs. Inspect the import blocks:

**copy and paste**

```bash
# Run from the factory1/ city directory.
cat pack.toml
```

**File contents**

```toml
[pack]
name = "factory1"
schema = 2

[imports]
[imports.gastown]
source = ".gc/system/packs/gastown"

[defaults]
[defaults.rig]
[defaults.rig.imports]
[defaults.rig.imports.gastown]
source = ".gc/system/packs/gastown"
```

What each block does:

- `[imports.gastown]` exposes the gastown pack's **city-scoped** agents (mayor, deacon, boot) to this city.
- `[defaults.rig.imports.gastown]` exposes the **rig-scoped** agents (witness, refinery, **polecat**) to every rig in this city.

Later pages of this tutorial customize behavior on top of gastown. When you no longer need a gastown agent, you can either delete one of these import lines or override individual agents in your own pack.

**Outcome:** `gc import list` (run from the city dir) shows two rows pointing at `.gc/system/packs/gastown`:

**Expected output**

```text
gastown              .gc/system/packs/gastown    (path)
default-rig:gastown  .gc/system/packs/gastown    (path)
```

### 3. Review the `city.toml` file

View the gastown init template's `city.toml`, including settings for prompt fragments and the daemon:

**copy and paste**

```bash
# Run from the factory1/ city directory.
cat city.toml
```

**File contents**

```toml
[workspace]
provider = "claude"
global_fragments = ["command-glossary", "operational-awareness"]

# [daemon]
# patrol_interval = "30s"
# max_restarts = 5
# restart_window = "1h"
# shutdown_timeout = "5s"

# [orders.overrides]
...
```

### 4. Set Dolt to auto-start

Ensure the Dolt server that stores beads starts automatically when the city restarts. Run from inside `factory1/`:

**copy and paste**

```bash
bd config set dolt.auto-start true
```

**Outcome:** `cat city.toml` shows `[workspace]`, your provider, the `global_fragments` line, and the `[daemon]` section.

## Troubleshooting

- **`gc init` does not list a gastown template option.** Re-run `gc version` — the gastown init template ships with `gc` 1.1.0+. Older versions list a different set.
- **`ls .gc/system/packs/gastown/agents` returns "No such file or directory".** `gc init` either failed mid-prompt or you ran a follow-up command from the wrong directory. From the parent of `factory1/`, confirm `factory1/.gc/system/packs/gastown/` exists; if not, re-run `gc init factory1` and pick the gastown template (`2`).
- **`cat pack.toml` shows different content than the file-contents block above.** A different config template was selected at `gc init` time. The fastest fix is to remove `factory1/` and re-run `gc init factory1`, choosing **gastown** (`2`).
- **`gc import list` shows zero rows.** The two `[imports.gastown]` blocks in `pack.toml` are missing or malformed. Compare yours to the file-contents block in step 2; both blocks must be present.
